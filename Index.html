02

The thesis running underneath the work

Most software waits. This work is an argument about what happens when it stops waiting.

Read the repositories in order and a single preoccupation repeats. Proto holds a long-lived goal, plans it, executes it in a sandbox and restarts itself if it dies — on your machine, with no cloud in the loop. Nyaya Sahayak carries fifty-three legal rights and twenty-five government procedures inside a phone that has no connection at all. NagarVault is specified for a municipal cluster that is not allowed to reach the internet. The Hadoop guide stands a cluster up on one laptop.

Across all of it, cloud services are treated as optional infrastructure rather than a foundation. And when something goes wrong, the answer is a watchdog process, an exponential back-off, a systemd unit, an NSSM service — not a support ticket.

The second pattern

The documentation is written as carefully as the software. An eighteen-section installation guide for one Hadoop cluster. A mandatory pre-task reading list for an unfinished operating system. Build provenance baked into an Android app so a bug report can name the exact commit it came from.

Note on method

The pattern above is a fact, read off the repositories. Any motive attributed to it is an inference, and is marked as one. Every quotation on this page is the author's own writing. Where a project is a fork or a team effort, it says so.

01

Agent systems Local inference

Proto

What happens when a system is expected to act rather than answer?

Year 2026 Status Experimental Licence AGPL-3.0 Built in Python · TypeScript

The repository description is unusually precise about what Proto is not: “Proto is a proactive agent, not a chat bot.” You hand it a long-lived goal. An HTN planner decomposes it into an ordered execution tree before anything is touched. The language model and a memory of past outcomes decide the next action. A sandbox screens every shell command and file operation against both Windows and POSIX destructive patterns.

Reporting is deliberately out of band. A Next.js dashboard streams live logs over WebSocket; a Baileys WhatsApp bot exposes ten owner-only commands so an agent can be paused, redirected or interrogated from a phone. Every process is independent — the dashboard can be down while the agent keeps thinking.

Inference runs on Ollama by default, and one environment variable swaps it for any OpenAI-compatible endpoint. Shipping it as a real service is part of the README rather than an afterthought: install_service.bat for NSSM on Windows, install_service.sh for systemd on Linux, four units in each case.

  • Episodic + vector memory
  • Sandboxed tool registry
  • Watchdog recovery
  • WebSocket dashboard
  • WhatsApp control
  • Ollama / OpenAI-compatible

02

Civic technology Offline-first

Nyaya Sahayak

Legal aid for the India that lives beyond wifi.

Year 2026 Status In development Licence AGPL-3.0 Built in React Native · Expo · TypeScript

Three hundred million Indians qualify for legal aid. Almost none receive it. The interesting technical decision here is the absence of a server: content lives in SQLite with FTS5 full-text search, maps are pre-bundled OpenStreetMap tiles rendered with Leaflet, and emergency contacts never leave the handset.

That constraint sets the rest of the design. Under fifty megabytes, launching in three seconds, on Android 8.0 — which is what a first-generation phone in a district court town actually is. A React Native 0.81 and Expo SDK 54 application, with react-native-reanimated doing the motion work on hardware that will not forgive it otherwise.

The repository carries the maintenance apparatus of something meant to last rather than a weekend prototype: Prettier and ESLint gates, Husky hooks that run a typecheck before every commit, Dependabot grouping Expo and React Native bumps, conventional-commit release scripts, three independent routes to a signed Android APK, and build provenance baked into the app so a bug report can name its own commit.

  • Offline OSM tiles

03

Systems In progress

Chimera OS

A modular, browser-based AI operating system — mostly still a plan.

Year 2026 Status Early, scaffolded Licence AGPL-3.0 Built in TypeScript, strict

Chimera is the most ambitious thing in the archive and openly the least finished. What exists is the scaffolding of a serious system: an event bus, a service registry with lifecycle management, typed configuration with a schema and a loader, structured error classes, and a provider router meant to abstract model backends.

The more revealing artefact is DEVELOPMENT_RULES.md — a mandatory pre-task reading list, a review checklist, a naming convention table, a commit format, and a closing argument that these rules “are the difference between a professional codebase and a pile of files.”

That gap between the ambition and the current state is the story. This is someone building the process for a multi-agent system before building the agents, because the process is the part that goes wrong.

04

Infrastructure Team project

NagarVault

What a city builds when its data is not allowed to leave the building.

Year 2026 Status Stack specified Origin Fork in account Runs on Kubernetes · Helm

“An air-gapped, privacy-first civic data operating layer for municipal intelligence.” The premise is a city whose records may not cross the building's network boundary, so the stack is correspondingly local and correspondingly heavy: FastAPI services, Kafka for ingestion, PostgreSQL for records, Qdrant for vectors, MinIO for objects, KONG as gateway, Elasticsearch and Prometheus for logs and metrics, deployed as a Helm chart with no cloud dependency.

The part worth pointing at is the small-model service on port 4004: a local language model that translates a natural-language question into SQL, against a schema indexer that has already embedded the database's own documentation into a vector store.

The security notes are the other half of the design — service-to-service tokens scoped to a named issuer and audience with a sixty-minute lifetime, httpOnly session cookies, a login endpoint rate-limited to five attempts per minute per address, and internal database and broker ports that simply do not exist on the host.

05

Desktop Released

Winget

The Windows package manager, given a face — and a Rust core behind it.

Year 2025 Status Released Licence MIT Built in Rust · TypeScript

Choosing Tauri over the obvious web-in-a-box route is the whole engineering decision: the logic is Rust, the interface is React and TypeScript, and the result is a native binary rather than a packaged browser. That is a heavier thing to build and a much lighter thing to run, which fits the rest of the archive.

Install, uninstall and upgrade with confirmation, layered validation before anything executes, an audit log, and a dashboard surveying the health of installed software — a package manager is a system administration surface, and it is treated as one.

There is also a register worth noting here. The README opens with a comment declaring the project the property of “the legendary Ojas Mohbansi” and describes the interface as “glassmorphism at its finest” — a joke that takes some confidence to publish directly above a real Rust codebase. Both things are true at once, and the juxtaposition is the most personal thing in the archive.

06

Security Prototype

VulnScanPro

Misconfiguration, not imagination.

Year 2025 Status Prototype Licence MIT Built in TypeScript

A deliberately narrow tool. Most scanners chase generic vulnerabilities across everything; this one goes after the mistakes that are peculiar to a framework — the ones that appear when React, Flask or Django is configured carelessly. That is a smaller claim than “security scanner”, and a more useful one.

It is TypeScript, MIT-licensed, and about two hundred kilobytes of repository. The README is two lines long, which suggests a premise its author did not think needed explaining.

It sits alongside the interest in ethical hacking and security work that runs through the profile, and follows the same instinct as the rest of the archive: look at the layer underneath the one everybody else has stopped looking at.

On the two identities

The earlier account publishes as S00K and presents itself as a black-and-green terminal belonging to “just another Programmer”, complete with fake shell output and a mission log. The current account drops the costume entirely and leads with the institution. The repositories moved accounts; the manner changed; the subject matter did not. This edition uses his name, and mentions the alias only where a repository is actually published under it.

Scale, stated plainly

These repositories have very few stars between them. What they do have is licences, changelogs, CI workflows, dependency bots, service installers, release scripts, issue templates and code-of-conduct rules — the apparatus of software that somebody intended to keep running. That is the more accurate measure of the work here, and it is why this issue leads with architecture rather than with numbers.
