## 02 Thesis

> ### Most software waits. This work is an argument about what happens when it *stops* waiting.

Read the repositories in order and a single preoccupation repeats. **Proto**
holds a long-lived goal, plans it, executes it inside a sandbox and restarts
itself if it dies — on your machine, with no cloud in the loop. **Nyaya
Sahayak** carries fifty-three legal rights and twenty-five government
procedures inside a phone that has no connection at all. **NagarVault** is
specified for a municipal cluster that is not allowed to reach the internet.
The Hadoop guide stands a cluster up on a single laptop.

Across all of it, cloud services are treated as optional infrastructure rather
than a foundation. And when something goes wrong the answer is a watchdog
process, an exponential back-off, a systemd unit, an NSSM service — not a
support ticket.

**The second pattern.** The documentation is written as carefully as the
software. An eighteen-section installation guide for one Hadoop cluster. A
mandatory pre-task reading list for an unfinished operating system. Build
provenance baked into an Android app so a bug report can name the exact commit
it came from.

**Note on method.** The pattern above is a fact, read off the repositories. Any
motive attributed to it is an inference, and is marked as one.<sup>2</sup>
Every quotation on this page is the author's own writing. Where a project is a
fork or a team effort, it says so.

### 01 Proto

**A proactive agent, not a chat bot.**

`2026` · `EXPERIMENTAL` · `AGPL-3.0` · `PYTHON · TYPESCRIPT`

*What happens when a system is expected to act rather than answer?*

<p align="center">
  <img src="./assets/plate-01-proto.svg" width="640"
       alt="Plate 01: a six-stage loop of decompose, decide, execute, remember, report and recover, with an oxide dot travelling down the spine">
  <br>
  <sub>PLATE 01 — THE LOOP · DRAWN FROM THE REPOSITORY'S OWN DOCUMENTATION</sub>
</p>

| Process or store | Responsibility |
| :-- | :-- |
| `SQLite` | episodic memory |
| `ChromaDB` | semantic recall |
| `FastAPI :8000` | agent · tasks · memory · logs |
| `Next.js :3000` | live log stream |
| `Baileys` | WhatsApp control, prefix `!` |
| `Watchdog` | heartbeat · back-off restarts |

The repository description is unusually precise about what Proto is *not*:
*"Proto is a proactive agent, not a chat bot."* You hand it a long-lived goal.
An HTN planner decomposes it into an ordered execution tree before anything is
touched. The language model and a memory of past outcomes decide the next
action. A sandbox screens every shell command and file operation against both
Windows and POSIX destructive patterns.

Reporting is deliberately out of band. A Next.js dashboard streams live logs
over WebSocket; a Baileys WhatsApp bot exposes ten owner-only commands so an
agent can be paused, redirected or interrogated from a phone. Every process is
independent — the dashboard can be down while the agent keeps thinking.

Inference runs on Ollama by default, and one environment variable swaps it for
any OpenAI-compatible endpoint. Shipping it as a real service is part of the
README rather than an afterthought: `install_service.bat` for NSSM on Windows,
`install_service.sh` for systemd on Linux, four units in each case.

`HTN planning` · `episodic + vector memory` · `sandboxed tool registry` · `watchdog recovery` · `WebSocket dashboard` · `WhatsApp control` · `Ollama / OpenAI-compatible`

Also published as a project site at [ojas-mohbansi.github.io/proto](https://ojas-mohbansi.github.io/proto/).

### 02 Nyaya Sahayak

**Legal aid for the India that lives beyond wifi.**

`2026` · `IN DEVELOPMENT` · `AGPL-3.0` · `REACT NATIVE · EXPO · TYPESCRIPT`

*Three hundred million Indians qualify for legal aid. Almost none receive it.*

<p align="center">
  <img src="./assets/plate-02-nyaya.svg" width="640"
       alt="Plate 02: four panes — know your rights, apply for, where to go, emergency SOS — with no server anywhere in the diagram">
  <br>
  <sub>PLATE 02 — FOUR SECTIONS, NO SERVER · RULES DRAW IN READING ORDER</sub>
</p>

| Section | Carries |
| :-- | :-- |
| **Know your rights** | 53+ fundamental rights and protections in plain language — Articles 14–32, labour law, women's rights, emergency provisions |
| **Apply for** | 25+ government documents and welfare schemes as numbered steps — Aadhaar, voter ID, ration card, RTI |
| **Where to go** | offices, legal aid centres and district courts on pre-bundled OpenStreetMap tiles, with GPS |
| **Emergency SOS** | one-touch alerts with location sharing to contacts stored only on the device |

**Seventeen languages, shipped offline.** Hindi · Tamil · Telugu · Bengali ·
Urdu · Marathi · Gujarati · Odia · Punjabi · Kannada · Malayalam · Assamese ·
Kashmiri · Kokborok · Nepali · Sanskrit · English

`under 50 MB` · `3-second launch` · `Android 8.0+` · `iOS 14.0+` · `zero data collection`

The interesting technical decision here is the absence of a server: content
lives in SQLite with FTS5 full-text search, maps are pre-bundled tiles rendered
with Leaflet, and emergency contacts never leave the handset.

That constraint sets the rest of the design. Under fifty megabytes, launching in
three seconds, on Android 8.0 — which is what a first-generation phone in a
district court town actually is. A React Native 0.81 and Expo SDK 54
application, with `react-native-reanimated` doing the motion work on hardware
that will not forgive it otherwise.

The repository carries the maintenance apparatus of something meant to last
rather than a weekend prototype: Prettier and ESLint gates, Husky hooks that
run a typecheck before every commit, Dependabot grouping Expo and React Native
bumps, conventional-commit release scripts, three independent routes to a
signed Android APK, and build provenance baked into the app so a bug report can
name its own commit.

`React Native 0.81` · `Expo SDK 54` · `expo-sqlite 16 · FTS5` · `offline OSM tiles` · `17 languages` · `CI: format · lint · typecheck`

**[View the repository →](https://github.com/ojas-mohbansi/nyaya-sahayak)**
Credited as founder and developer, with Pranav Prasoon as co-founder. Project site: [ojas-mohbansi.github.io/nsw](https://ojas-mohbansi.github.io/nsw).

`2026` · `EARLY, SCAFFOLDED` · `AGPL-3.0` · `TYPESCRIPT, STRICT`

*What exists is the scaffolding of a serious system. The gap is the story.*

| Module | Contents |
| :-- | :-- |

| `config/` | schema · loader · defaults |
| `agents/` | planner · architect · coder · reviewer · debugger · researcher · security · devops · memory · orchestrator — *planned* |
| `api/` | route handlers |
| `extensions/` | command registry |
| `skills/` | skills engine — *planned* |
| `memory/` | memory system — *planned* |

**What the rules require before any code.** Read `ARCHITECTURE`, `DECISIONS`,
`TASKS`, `BUGS` and `PROGRESS` before starting a task. Search the codebase for an
existing implementation before creating a file. Keep functions under fifty lines
and files under three hundred. Then update the changelog, progress log, task
list and API document — every time.

Chimera is the most ambitious thing in the archive and openly the least
finished. What exists is the scaffolding of a serious system: an event bus, a
service registry with lifecycle management, typed configuration with a schema
and a loader, structured error classes, and a provider router meant to abstract
model backends.

The more revealing artefact is `DEVELOPMENT_RULES.md` — a mandatory pre-task
reading list, a review checklist, a naming convention table, a commit format,
and a closing argument that these rules *"are the difference between a
professional codebase and a pile of files."*

That gap between the ambition and the current state is the story. This is
someone building the process for a multi-agent system before building the
agents, because the process is the part that goes wrong.

`event bus` · `service registry + lifecycle` · `typed config schema` · `provider router` · `MCP` · `CodeQL · Trivy · Dependabot` · `36 KB changelog`

### 04 NagarVault

**What a city builds when its data is not allowed to leave the building.**

`2026` · `STACK SPECIFIED` · `TEAM PROJECT` · `KUBERNETES · HELM`

*"An air-gapped, privacy-first civic data operating layer for municipal intelligence."*

<p align="center">
  <img src="./assets/plate-04-nagarvault.svg" width="640"
       alt="Plate 04: seven services sealed inside a boundary, facing a dashed air gap that a blocked request reaches and does not cross">
  <br>
  <sub>PLATE 04 — THE BUILDING AND THE WALL · A REQUEST REACHES THE GAP AND STOPS</sub>
</p>

| Port | Service | Responsibility |
| :-- | :-- | :-- |
| `4000` | Auth | login, logout, profile, user creation |
| `4001` | Admin | cluster health, audit logs, dead-letter queue, vector re-sync |
| `3000` | Ingestion | presigned uploads, event ingestion |
| `4003` | Query | SQL execution with role-based access control |
| `4004` | SLM | a local language model turning natural language into SQL |
| `4005` | Schema indexer | embeds database documentation into Qdrant |
| `5173` | Interface | Next.js |

Infrastructure — PostgreSQL, Kafka, Qdrant, MinIO, Redis, Ollama — is
deliberately not bound to the host in production.

The premise is a city whose records may not cross the building's network
boundary, so the stack is correspondingly local and correspondingly heavy:
FastAPI services, Kafka for ingestion, PostgreSQL for records, Qdrant for
vectors, MinIO for objects, KONG as gateway, Elasticsearch and Prometheus for
logs and metrics, deployed as a Helm chart with no cloud dependency.

The part worth pointing at is the small-model service on port 4004: a local
language model that translates a natural-language question into SQL, against a
schema indexer that has already embedded the database's own documentation into
a vector store.

The security notes are the other half of the design — service-to-service tokens
scoped to a named issuer and audience with a sixty-minute lifetime, httpOnly
session cookies, a login endpoint rate-limited to five attempts per minute per
address, and internal database and broker ports that simply do not exist on the
host.

`FastAPI` · `Kafka` · `PostgreSQL` · `Qdrant` · `MinIO` · `KONG` · `Elasticsearch · Prometheus` · `local SLM → SQL`

**[View the repository →](https://github.com/ojas-mohbansi/nagarVault)**
Appears in the account as a fork, so authorship is treated here as a team effort rather than a solo credit.

Install, uninstall and upgrade with confirmation, layered validation before
anything executes, an audit log, and a dashboard surveying the health of
installed software — a package manager is a system administration surface, and
it is treated as one.

There is also a register worth noting here. The README opens by declaring the
project the property of "the legendary Ojas Mohbansi" and describes the
interface as "glassmorphism at its finest" — a joke that takes some confidence
to publish directly above a real Rust codebase. Both things are true at once,
and the juxtaposition is the most personal thing in the archive.

### 06 VulnScanPro

**Misconfiguration, not imagination.**

`2025` · `PROTOTYPE` · `MIT` · `TYPESCRIPT`

*The repository documents its premise in two lines, so the plate is two lines.*

<p align="center">
  <img src="./assets/plate-06-vulnscan.svg" width="640"
       alt="Plate 06: the two-line premise in italic serif, with a scan crossing the React, Flask and Django chips">
  <br>
  <sub>PLATE 06 — SCOPE, STATED IN FULL · THE SCAN CROSSES EACH FRAMEWORK IN TURN</sub>
</p>

> "New open-sourced vulnerability scan. Target framework-specific
> misconfigurations in React, Flask, and Django apps."

A deliberately narrow tool. Most scanners chase generic vulnerabilities across
everything; this one goes after the mistakes that are peculiar to a framework —
the ones that appear when React, Flask or Django is configured carelessly. That
is a smaller claim than "security scanner", and a more useful one.

It is TypeScript, MIT-licensed, and about two hundred kilobytes of repository.
The README is two lines long, which suggests a premise its author did not think
needed explaining.

It sits alongside the interest in ethical hacking and security work that runs
through the profile, and follows the same instinct as the rest of the archive:
look at the layer underneath the one everybody else has stopped looking at.

`TypeScript` · `MIT` · `framework misconfiguration` · `open source`

**[View the repository →](https://github.com/ojas-mohbansi/vulnscanpro)**
